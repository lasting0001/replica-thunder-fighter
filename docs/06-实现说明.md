## 1. 工程结构

```
replica-thunder-fighter/
├── index.html          # 入口：舞台、Canvas、各屏幕 DOM、按序引入脚本
├── src/
│   ├── style.css       # 全部界面样式（cqh 等比缩放，竖屏 9:16）
│   ├── config.js       # 常量、手感参数 CFG、战机表 SHIPS、关卡表 LEVELS
│   ├── audio.js        # WebAudio 合成音效（Sound）
│   ├── core.js         # 画布/DPR、全局状态 G、星空、背景、贴图、存档、屏幕路由、绘制工具
│   ├── battle.js       # 战斗：生成器、更新、碰撞、HUD、特效、战斗输入
│   └── app.js          # 应用层：导航、星图、仓库、设置、结算、主循环
├── demo/index.html     # 阶段 3 验收 Demo（保留对照）
├── docs/               # 01–06 阶段文档
└── assets/             # 预留（当前美术全部程序化绘制，无外部资源）
```

脚本使用经典 `<script>` 按 `config → audio → core → battle → app` 顺序加载，`file://` 下可直接运行。

## 2. 状态机与数据流

### 2.1 屏幕路由（`Screen`）

```
title ──开始──> home ──星际征战──> map ──出击──> battle
                  ├──无尽挑战──> battle(endless)
                  ├──仓库──> hangar ──返回──> map/home
                  └──设置──> settings ──返回──> home

battle ──暂停──> pause ──继续──> battle
   │                ├──重新开始──> battle（保留 story/endless 模式）
   │                └──放弃──> map（无尽→home）
   ├──故事：胜利/坠毁──> result ──下一关/再战──> battle
   │                     ├──星图──> map
   │                     └──主界面──> home
   └──无尽：坠毁──> result(ENDLESS RUN) ──再战──> battle(endless)
```

- 屏幕切换统一走 `Screen.show(id)`，用 `.screen.active` 控制显隐；战斗无 DOM 覆盖层，`Screen.current = 'battle'`。
- 战斗内状态由 `G.state` 管理：`playing / paused / victory / defeat / menu`。

### 2.2 战斗循环

`requestAnimationFrame` 驱动，逻辑固定步长 `1/60s`，最多补 5 步：

```
App.frame → Stars.update → Battle.update(1/60) × N → Battle.render
```

- `G` 持有全部实体数组：`bullets / ebullets / enemies / pickups / particles / texts / boss`。
- 关卡脚本 `LEVELS[i].waves` 按时间升序执行，`G.si` 为游标。
- 结束条件：BOSS 关 = BOSS 三条血清空；非 BOSS 关 = 脚本执行完且场上敌机清空 → 1s 后结算。
- 结算回调 `Battle.onEnd(win)` 由 `App` 注入，统一处理奖励、解锁、最高分与存档。

### 2.3 存档（`Save`）

- key：`tf_replica_save_v1`，JSON 结构（version 2）：

```js
{ version:2, bestScore, coins, shards, gems,
  progress:{ unlocked, cleared },
  ships:{ equipped, levels:{assault,spike,falcon}, stars:{...} },
  endless:{ bestScore, bestWave },
  settings:{ volume, muted, quality } }
```

- 读取时逐字段校验并合并默认值（v1 旧档缺 `ships.levels/stars`、`endless` 时自动补默认值，等效迁移）；JSON 损坏或隐私模式写入失败均静默回退，不阻断游戏。

## 3. 数据表位置

| 数据 | 位置 | 说明 |
|---|---|---|
| 手感参数 | `config.js` → `CFG` | 玩家速度/判定/射速/弹道、敌机、BOSS、掉落率，与 Demo 一致 |
| 战机 | `config.js` → `SHIPS` | 3 架：突击/尖峰/猎鹰，含血量、伤害、射速系数、弹道偏移、配色 |
| 章节 | `config.js` → `CHAPTERS` | 白羊座、金牛座 |
| 关卡 | `config.js` → `buildLevel()` / `LEVELS` | 16 关，波次时间轴、掉落时间点、BOSS 参数、推荐战力、奖励、掉落摘要 |
| 成长 | `config.js` → `SHIP_PROG` | 等级上限（25/40/55）、强化/进阶消耗、属性倍率 |
| 无尽 | `config.js` → `ENDLESS` | 开场延迟、波次间隔、每 5 波 BOSS、警告时长 |
| 画质 | `config.js` → `QUALITY` | 粒子数量倍率（高/中/低） |
| 音频 | `audio.js` → `Sound` | 11 种合成音效 |

关卡 `waves` 的步骤类型：`line`（直线）、`v`（V 字）、`divers`（自杀机）、`fighters`（中型机）、`drop`（掉落）、`warn`（警告）、`boss`（入场）。

## 4. 已实现（M0 + M1 + M2）

- 工程骨架、屏幕路由、加载即用、无外部依赖。
- 标题 / 主界面（战机展示、资源栏、无尽最高波与最高分、入口）/ 星图（两章 16 关、解锁、推荐战力、奖励与掉落预览）/ 仓库（3 架战机、属性条、等级/星级/战力、强化、进阶、切换出战）/ 设置（音量、静音、画质、清档）/ 结算（故事与无尽两套）/ 暂停。
- 战斗完整闭环：玩家、三类杂兵、道具、BOSS、碰撞、计分、暴走、必杀、护盾、回血。
- 数据驱动 16 关：9 波固定节奏 + 6 次掉落 + 第 4/8/12/16 关 BOSS（3 管血 3 阶段）。
- 战机成长：残骸强化（每级 +2% 攻击/生命）、满级后进阶（+1 星，每星 +12%，上限 3 星），战力 = 基础战力 × 倍率，实时作用于生命与伤害。
- 无尽模式：动态波次（间隔随波数递减、强度递增）、每 3 波掉落武器、每 4 波护盾、每 5 波「无尽守卫」BOSS；坠毁后结算最高波与无尽最高分，可再战。
- 存档持久化：最高分、金币、残骸、关卡进度、装备战机、战机等级/星级、无尽记录、设置；刷新后保留，旧 v1 档自动补齐字段。
- 音效首次手势解锁；音量与静音持久化；画质影响粒子数量。
- 键盘：方向键/WASD 移动、空格必杀、P/Esc 暂停；触屏/鼠标相对拖拽 1:1。

## 6. 与规格的偏离

| 项 | 规格/计划 | 实现 | 原因 |
|---|---|---|---|
| 关卡时长 | 参考 Demo 约 41s | 非 BOSS 关约 38–40s，BOSS 关约 45–60s | 使用统一 9 波节奏 + 固定掉落点，便于数据化扩展 |
| BOSS 种类 | M3 做 3 种 | 当前 1 套 3 阶段 BOSS，两章换配色与名称 | 属 M3 范围，M1 先保证机制闭环 |
| 仓库强化 | M2 开放 | 已开放：残骸强化 + 星级进阶（3 星） | 统一用残骸作唯一材料，未拆分强化石 |
| 无尽模式 | M2 开放 | 已开放：动态波次 + 每 5 波 BOSS + 最高波/分 | 波次强度按线性系数增长，未做手写波表 |
| 分解奖励/关卡评价 | M2 计划 | 未做 | 结算已有金币/残骸与无尽统计，评价体系留待 M3 统一设计 |
| 关卡背景 | M3 两章差异化 | 已做两套背景配色（星云/赤褐） | 低成本先满足辨识 |
| 音效数量 | 9 种 | 11 种（含按钮音） | 小幅补充 |

## 7. 已知限制

- 关卡内容为数据生成，尚未逐关手工调难度；第 4 关起需要移动规避，站桩会被击毁。
- 无尽模式波次与 BOSS 为同一套参数缩放，长局可能出现重复感，待 M3 增加 BOSS 形态。
- 战舰与 BOSS 为程序化矢量绘制，与原作造型仍有差距（M3 统一打磨）。
- 未做横屏提示与低端机帧率自适应（M3）。
- 无 BGM（M3）。
- 测试角色自动站桩时无法击破正式 BOSS，属操作问题而非逻辑缺陷；联调版已验证击破与结算链路。
