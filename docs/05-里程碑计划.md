## 2. M0 框架（P0）

**交付**

- 目录：`index.html`（入口）、`src/style.css`、`src/config.js`、`src/audio.js`、`src/core.js`、`src/battle.js`、`src/app.js`（经典脚本，`file://` 可直接加载，不用 ES Module）。
- 屏幕状态机：`S_TITLE → S_HOME → S_MAP / S_HANGAR / S_BATTLE → S_RESULT`，任意屏幕可暂停/返回。
- 全局存档对象：`{ version, bestScore, coins, shards, ships, equipped, progress, settings }`，localStorage 持久化，带版本迁移占位。
- 输入层：Pointer Events 相对拖拽、键盘、按钮；统一 `hitTest`。
- 音频：首次手势解锁；master gain；静音持久化。
- 渲染：720×1280 逻辑分辨率、固定步长、分层绘制、资源离屏缓存。

**验收**

1. 连续切换所有屏幕 50 次无异常、无内存暴涨。
2. 空场景跑 60 秒，帧率稳定；无控制台错误。
3. 静音与设置刷新后保留；存档损坏时回退默认值不崩溃。

**不做**：正式美术、音乐、关卡内容、强化逻辑。

## 3. M1 核心闭环（P0）

**交付**

- 战斗场景完整：玩家、三类杂兵、道具、OBSTACLE（陨石）、BOSS、弹幕、碰撞、计分。
- 数据表：`levels.js` 描述每关波次、BOSS、掉落、推荐战力；`ships.js` 描述三架战机弹道与数值。
- 一局流程：关卡开场 → 波次 → BOSS 警告 → BOSS → 胜利/失败 → 结算 → 返回地图/重开。
- 手感参数沿用 `02` 规格；与 Demo 对比不得出现明显偏差。

**验收**

1. 任意关卡可完整跑通，无卡死、无数组越界、无未清理定时器。
2. 火力 1–4、暴走、必杀、护盾、回血、水晶全部可用。
3. BOSS 三管血三阶段可击破；失败与胜利结算数据正确。
4. 与 Demo 的手感对照：拖拽 1:1、判定点、射速、弹速一致。

**不做**：主界面装饰、仓库、地图剧情、无尽模式。

## 4. M2 周边系统（P1）

**交付**

1. **主界面 S_HOME**：战机展示台（呼吸/尾焰动画）、入口按钮（星际征战/无尽挑战/仓库/设置）、玩家资源栏（金币/残骸/钻石占位）。
2. **闯关地图 S_MAP**：两章 16 关节点路线、关卡详情（敌方战力、体力/次数占位、掉落预览）、解锁规则；推荐战力不足时红字提示但允许强制挑战。
3. **仓库 S_HANGAR**：3 架战机与装甲/副武器/僚机（各 3 件占位）；强化（消耗残骸，等级 1–25）；进阶（满级 + 材料 → 星级提升，攻击/生命成长）；装备切换影响战斗。
4. **无尽模式**：从第 1 波开始无限刷怪，每 5 波一个 BOSS 轮换；分数与本地最高分；失败结算。
5. **结算 S_RESULT**：胜负、得分、击毁、水晶、获得残骸/金币、最高分、再战/下一关/返回。
6. **设置**：音量、静音、画质（粒子数量）、清除存档。
7. **存档**：以上全部持久化；版本号与默认值合并。

**验收**

1. 每关解锁条件与进度正确；退出重进进度不丢。
2. 强化/进阶后战力、攻击、生命按表变化；装备切换在战斗中生效。
3. 无尽模式可连续刷 10 波以上不崩；分数与最高分正确。
4. 三个系统（地图、仓库、无尽）都能独立完成一次完整操作。

**不做**：战神合体、驾驶员、战队、PVP、内购、真实体力恢复。

## 5. M3 打磨（P1）

**交付**

- 美术：三架战机差异化外观、4 种杂兵、3 种 BOSS（红色重装机/布莱特/金牛座守卫）、两章背景（星云/空间站）、道具与爆炸特效统一风格。
- 音频：9 种音效定稿，新增 2 首程序化 BGM（标题/战斗），音量分轨。
- 动效：屏幕转场、按钮反馈、BOSS 入场、结算数字滚动、受伤与暴走画面效果。
- 性能：粒子池、子弹池、离屏缓存、避免每帧创建渐变；目标 60fps。
- 响应式：横竖屏提示、刘海安全区、低端机降级（粒子上限）。

**验收**

1. 与参考结构逐屏对照无明显偏差（截图并排检查）。
2. 中端手机浏览器 60fps，连续 3 局无内存增长异常。
3. 触屏与键鼠均可完成全部操作；音频可静音且状态保留。

1. 阻断级缺陷为 0；高危缺陷有明确遗留说明。
2. 全部屏幕与系统可离线运行，无外部依赖与网络请求。
3. 用户按 `08` 对照表逐项验收通过。

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 原作无精确数值 | 手感偏差 | 以 Demo 已验收参数为基线，所有调整集中 `config.js` |
| 16 关内容量大 | 进度拖延 | 关卡完全数据化，先做 4 关模板再批量填充 |
| `file://` 限制 | 模块/资源加载失败 | 只用经典 `<script>` 与内联/离屏资源，不 fetch 本地文件 |
| 移动端性能 | 掉帧 | 对象池 + 粒子上限 + 预渲染贴图 |
| 存档结构变更 | 旧档失效 | 存档带 version，合并默认值，异常回退 |

## 8. 里程碑门控

- M2 完成 → 逐系统演示 → 确认后开 M3。
- M3 完成 → 截图对照与性能数据 → 确认后开 M4。
- M4 完成 → 测试报告与验收对照表 → 最终交付。
